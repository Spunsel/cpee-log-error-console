CPEE LLM Debugging Console

A post-hoc analysis tool that loads a CPEE modification log, reconstructs each LLM modification step, and lets you inspect all five pipeline stages as interactive graphs. Enter a process number or UUID to load an instance; the console fetches the .xes.yaml log, filters description/exposition events, and assembles them into a numbered step sequence. Multiple instances can be loaded simultaneously via sidebar tabs.

Step Navigation

Each step = one user–LLM modification round. Navigate with Prev/Next buttons, the step dropdown.

The Five Content Sections

Each step is split into five sections corresponding to the pipeline stages:

Section 1 — Input CPEE

Process model before modification, rendered as a native CPEE graph (WfAdaptor).

Section 2 — Input Mermaid

The Mermaid diagram generated from the Input CPEE and sent to the LLM.

Section 3 — User Input

The natural-language instruction the user gave to the LLM.

Section 4 — Output Mermaid

The LLM's Mermaid output, rendered with automatic syntax-error correction.

Section 5 — Output CPEE

Final process model after Mermaid-to-CPEE back-conversion, rendered as a CPEE graph.

View Modes

Each section supports five view modes:

☷ Graph ✓ Cleaned ▶ Raw → Traces ◡ Analysis

Graph

Interactive visual graph — zoomable and clickable.

Cleaned

Source code with preprocessing fixes applied.

Raw

Exact unmodified content from the cpee:exposition log field.

Traces

All possible execution paths (start → end). Includes animated playback.

Analysis

Soundness, boundedness, reachability checks with pass/fail status per property.

Cross-Graph Highlighting

Click any task in a Graph view to highlight the same task across all other open graph sections simultaneously.

Trace Analysis & Comparison

Traces are computed for the input-side (Stages 1 & 2) and output-side (Stages 4 & 5) graphs and compared. Each trace is classified as:

Matching

Present in both before and after — modification preserved this path.

Unique

Present in only one graph — path was added or removed by the modification.

Reconciled

Initially unique, but matched via more relaxed conditions.

Structural Analysis

Each graph section can be checked for four formal properties:

Soundness

Process always terminates; every task is reachable.

Boundedness

No unbounded token accumulation at any node.

Reachability

Classifies nodes as reachable, unreachable, or dead-end.
